# LARK / THE BLUE SQUIRE｜Sprite Stacking 人型アニメーション 第2段階

**共通の関節付き断面モデルから、歩行・斬撃を各6コマ×8方向で生成できた。** 歩行は48×48 px。攻撃は原寸のキャラクターを縮めず、剣先のために64×64 pxに余白を確保した。右手の剣と左手の盾は全ポーズで同じ手に固定される。一方、背面では攻撃の一部が身体に隠れ、エフェクトなしで攻撃の瞬間を全方向から同じように読ませることはできなかった。

## 1. 実装と前回からの変更

- **そのまま再利用したもの**：前回の素材ID断面（80×60×32層）、パレット、輪郭色、静止48/96 pxシート、メタデータ。静止シートおよび攻撃の第1・6コマは前回画像とピクセル単位で一致。攻撃の両端は、関節変形なしで元の素材配列に戻ることも検査した。
- **追加**：頭・胸・腰、左右の上腕／前腕／手、左右の太もも／すね／ブーツ、剣、盾の17部位に素材セルを分類。腕・脚は固定長の2関節IKで手足の目標位置から肘・膝を解く。剣・盾はそれぞれ右手・左手の剛体変換を共有し、休止時の取り付け位置を局所座標で維持する。剣を身体の中心線より反対側に振っても持ち手は変わらない。
- **描画**：Python・NumPy・Pillow。各姿勢を逆変換による最近傍サンプリングで0.5モデル単位の水平断面へ戻す。各姿勢は同じ96×96の格子で最大92層を保持する（上下の空層を含む）。同一断面を正投影、俯角24°、方位45°刻み、1.19 px/モデル単位で描画する。各画素で手前の実セルを採用し、外周線を後から1 px付けた。方向別の描き直し、水平反転、斬撃エフェクトなし。
- **Phase A→B**：SW・NEで先に比較。初回の振りかぶりは剣が頭の後ろに隠れたため、手を外へ、剣を外上へ向けた。振り切りの剣が視線軸に近かった試行を下向きに変更し、NEの剣身可視が1 pxから5 pxに改善。その上で8方向を出力した。Wの攻撃3コマ目では48 pxの上端に触れたため、全攻撃コマを同じ解像感のまま外側へ8 pxずつ広げた。

### 数値・実行の検証

- **接地**：歩行は1コマごとに前へ1.9モデル単位移動する前提のその場歩き。周期またぎを含め、同じ足が接地する4姿勢の足裏マーカーは、進行を足すと床面上の同一点に留まった（計算誤差以下、全方向投影0 px）。各姿勢の最下の靴ボクセルも床面ちょうど。これは連続補間・他の移動速度・画像の見た目の足滑りまでは保証しない。
- **輪郭**：歩行の最後→最初のアルファ輪郭IoUは0.873〜0.943。全方向の隣接コマ中の最小値は0.861。大きな継ぎ目がない目安であり、色や細部のちらつきとは別。
- **遮蔽**：剣身・盾を同じ姿勢で単独描画した場合と比較。NWの斬撃は48 px相当で剣身0/21 px、高解像度でも0/87 px、Nの振り切りは0/21→0/84 px。Wの振り上げは0/15→4/74 px、NEの振り切りは5/15→22/65 px。ゼロのままの箇所は主に身体の遮蔽で、解像度を上げても解消しない。画素数は形状を読めることと同義ではない。
- **画像規格**：PNG2種は各48コマ、アルファ0/255のみ、最終セルで端切れなし。攻撃の手と剣先の距離は全キーで約11.6865モデル単位。GIFを実際にデコードして6コマと各時間を確認し、8方向の出力一覧も目視で比較した。実環境のChromiumではローカルHTMLを開く操作まで試したが、組織ポリシーで `file://` 表示が遮断された。プレビューはNodeのモックで8方向の切り出し、48/64の中央揃え、FPS・コマ送り・一回再生を検査済み。実ブラウザー上の再生、ゲームエンジンへの組み込みは未確認。
- **再現性**：同じ入力から別フォルダーに再生成し、納品版とPNG・GIF・JSONのバイトおよび全13姿勢の断面配列が一致した。照合手順も同梱。

## 4. 技術比較

A・Cは今回実装していないため、以下は設計上の比較。

| 方式 | 見た目と方向整合 | 制作・モーション再利用・量産 | 複雑さ |
|---|---|---|---|
| A：コマごとに独立した断面 | 特定の決めポーズを手で整えやすい。同一コマ内の方向は揃うが、コマ間の体型や装備位置は別途管理 | 単発ポーズは簡単。体形・武器・コマが増えるほど手作業が増え、共有しにくい | 描画は単純、素材の管理は重い |
| B：関節で立体部品を動かし再スライス | **今回実証**。体形と持ち手を維持しつつ遮蔽を解ける。剛体パーツの境目・表面の量子化は残る | 名付き関節と同一規格で動作を追加・再利用しやすい。胴のひねりや違う頭身では関節・接地を再調整 | 部位分割、IK、ボクセル化と深度描画が必要 |
| C：低ポリ3Dをリグで動かし焼く | 捻りや膝・肘の曲げで、ウェイト付きの連続形状を作りやすい。48 pxの質感・視認性は別に調整 | 既存リグやリターゲットを使える規模で有利。モデリングとピクセル向けの焼き設定が必要 | 既製ツールは豊富だが初期リグとアセット規格が重い |

## 5. 実用判定

- **静止8方向：有望**。既存シートを維持できた。
- **歩行8方向：有望**。小さな歩幅のループとして成立。移動速度を合わせた実ゲームで足滑りを再確認したい。
- **攻撃8方向：条件付きで有望**。構え・斬撃の差は出たが、背面での遮蔽と6コマの軌道飛びが限界。
- **装備差し替え：条件付きで有望**。取り付け点と部位を分離した。他の装備で握り・干渉・セル余白を試していない。
- **別キャラへのモーション転用：未確認**。関節名は再利用できるが、頭身や手足の長さが違うモデルで未試験。
- **ゲームへの組み込み：条件付きで有望**。PNG・アンカー・描画引数の検証済み。実端末での再生とゲーム側の当たり判定は未確認。

## 6. プレビューと再生成

ZIPを展開して `preview.html` と同じ階層の `output/` を残したまま開く。原寸モードはステージの拡大を止めるだけで、攻撃の人物をリサイズしない。一覧の方向行順は **S / SW / W / NW / N / NE / E / SE**、横は時間順です。歩行は9 FPS推奨、攻撃は等速なら10 FPS、見本のリズムを使うなら `metadata.json` のコマ別ミリ秒を使用。プレビューのFPSスライダーは等速比較用。画像補間はオフにし、セル単位のアンカーを地面座標に合わせる。上下左右に余白を持つ攻撃セルをそのまま描画しても、キャラの足元はずれない。

```sh
python -m pip install -r requirements.txt
python animate.py --phase A --out phase_a
python animate.py
python rig_diagram.py
python animate.py --out rebuilt
python verify_outputs.py --compare rebuilt
node verify_preview.cjs
```

**次の最小実験**：攻撃の「振り上げ→切り込み」「切り込み→振り切り」に各1コマを追加。SWだけでなくNW/Nも同時に焼き、剣の先端の移動量と識別性を比較する。背面で剣身が完全に消える箇所は、効果線に頼る前に右肘の前後位置と胸のひねりを調整する。歩行は代表1方向を実ゲームの移動速度で動かし、その場GIFでは見えない足滑りを確認する。
