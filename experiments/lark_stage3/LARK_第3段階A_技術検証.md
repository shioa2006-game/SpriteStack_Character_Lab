# LARK / THE BLUE SQUIRE
## 第3段階A：歩行・斬撃の品質改善とRPG想定検証

### 1. 結論

**歩行は2D RPGへの組み込み候補。斬撃はN・NEで明らかに読みやすくなったが、NWと一部側面は条件付き。** 同じ立体モデル・モーションで全8方向を生成し、方向別補正、水平反転、左右の持ち替えは行っていない。原寸では、N・NEでも剣を「上げる→外側を通る→下ろす」と読めるようになった。NWは旧版の完全遮蔽を減らせたが、頭や肩の外に現れる部分が短く、原寸の一瞬だけでは斬撃と断定しづらい。8方向すべてで十分読みやすいという成功条件は未達。

画像・GIFでは、歩行の上下動を抑えたことで足の交互運動が目に入りやすい。ただし6コマのままなので、床と同期しても低速や急停止の切り替えには段差が残る。ブラウザ用の操作環境は作成し、実PNGを用いたCanvas描画と操作ロジックを実行検証したが、今回の環境ではChromiumでの実操作までは確認できなかった。人間が繰り返し操作したときの気持ちよさや本番ゲームへの組み込みは未検証。

### 2. 継承したものと変更点

- 旧版のコード、モーション、静止PNG、歩行・攻撃PNG/GIF、測定値は `baseline/` に保存。既存キャラクターのポーズ分割、17部位の割当、32層の元モデル、右手の剣・左手の盾、カメラとパレットを継承。新版の静止8方向PNGは旧版とバイト一致。
- カメラは正投影、仰角24°、1.19px/モデル単位、45°刻み。全ポーズを部位別の関節変形と2関節IKで作り、0.5単位の水平層へ再サンプリング。手・武器は同じ剛体変換。ピクセル補間・アンチエイリアスなし。
- 歩行（`walk_motion.py/json`）：左右の足跡幅を片側0.36単位外に開き、遊脚の持ち上げを調整。支持脚が後方へ送られる距離と地面上の前進距離（1.9単位/コマ）を維持。頭は胸のヨー角の追従を止め、小さな上下・左右移動に限定。肩と腕の振幅を抑え、装備の振れを少なくした。
- 斬撃（`attack_motion.json`）：右手を身体外に通し、肘を支点に剣先が上から外へ落ちる弧を作った。胸のひねりと肩の向きを組み合わせ、振り始めと振り切りの間に下降コマを追加。剣を伸ばす・位置を画面上に貼るような処理はしていない。
- 48px原寸内に人物の縮尺を維持。歩行は48×48、攻撃は剣先用の周囲8px余白を含む64×64。軸足を隠す影はPNGに焼き込まず、比較用の床は別描画。攻撃の初・終盤の構えは旧静止画と一致。

#### 斬撃：コマ数とテンポ

改良版から同じ800ms、共通のポーズを抜き出し、6・8・9コマを並べた（`attack_sample_count.gif`）。6は準備・復帰の一部、8は斬撃中の下降を省略。最大距離は29.61/20.72/17.46、主斬撃から振り切りの区間では20.72/20.72/12.77モデル単位。6コマは剣が低い構えから上へ出る間を省きすぎ、8コマでは上から斜め下まで一度に飛ぶ。9コマはN・NEで「横を通って下がる」一瞬が読めるので採用した。6コマ旧版と新版の比較だけでは、ポーズの変更とコマ追加を切り分けられないため、この共通ポーズ比較を併用した。

可変配分は `75,85,105,105,45,50,95,100,140ms`。同じ800msの等間隔（約89ms×9）と比較。可変版は振り上げとひねりを計210ms見せ、斬撃・下降を計95msで通過。絵を見た範囲では、均等版より溜めと切り落としの差が分かりやすい。斬撃の最初の視覚反応75ms、主斬撃370ms、構え復帰660ms、拘束解除800msは別の値。テンポの速いアクションRPGにはこのままだと重く感じる可能性がある。攻撃の当たり判定はなく、ヒット時刻を実証していない。GIFの境界は10ms刻み、末尾に比較用の休止を足している。正確な時刻はJSONが基準。

#### エフェクト

`attack_optional_trail.gif` だけで、主斬撃の1コマに、同じ3D剣先軌跡を投影した1px幅の短い線を比較。絵の不透明部分を上書きしない。NEではわずかに速度方向を補うが、Nでは刃と重なってほとんど差が出ない。NWでは手元の関係までは補えず、剣先が髪の横にある問題を解決しない。シート本体と操作プレビューでは不採用。ヒットストップは試していない。

#### 足の接地と輪郭

両足とも支持区間（左0→3、右3→次ループ0、0始まり）で同じつま先マーカーを追い、床z=0、目標との誤差・進行方向の累積ずれともゼロ。支持足底の最低ボクセルもz=0。遊脚の最低ボクセルは1.0/1.5→2.0/2.0単位で、床から離れる瞬間が分かりやすい。整数丸めを入れた共通原点のサンプルでは、コマの境目に縦0px、他方向最大1pxの丸めずれ。これは旧版も成立しており、改善は接地数値ではなく動きの見え方。保持中は体だけが滑らかに進むので横最大2.26px相当の靴の行き戻りが理論上残る。低速で一コマが長いと見えやすい。

髪の安定化は全方向で一様ではない。歩行で隣接コマの頭IDマスクを画面平行移動で合わせる `verify_walk.py` の指標は、Nで平均22.00→8.67px、NEで24.00→12.00px、Wで13.33→15.33px。これは頭部の形と遮蔽を含む差で、色ちらつきだけを対照にした測定ではない。GIFでは正面・背面の頭の揺れが減って見える一方、Wの髪や側面の靴先には小さな1px級の変化が残る。

### 5. 実ゲーム想定の検証

`LARK_Preview_Standalone.html` をダウンロードしてブラウザで開く。素材は同梱済みで外部通信なし。`preview.html` を使う場合は、ZIP展開後に同階層の `preview_assets.js` を保持。矢印/WASDで8方向移動、止めると構え、Space/Jまたは斬撃ボタンで1回振る。旧・新の切替、歩行同期解除、再生倍率、可変/均等の斬撃タイミング、原寸/整数倍とアンカー表示あり。攻撃中は向きと移動を固定する検証仕様で、キャンセルや入力予約は未実装。

| 歩行レート | 移動（モデル単位/秒） | 再生FPS | 原寸での横 / 縦移動（px/秒） |
|---|---:|---:|---:|
| ×0.6 | 10.26 | 5.4 | 12.21 / 4.97 |
| ×1.0 | 17.10 | 9.0 | 20.35 / 8.28 |
| ×1.6 | 27.36 | 14.4 | 32.56 / 13.24 |

縦移動は固定カメラの床面短縮（sin24°）を反映。歩行GIFは動かない床の上で旧新の開始位置と速度を揃え、各条件を別ファイルにした。同じ距離を移動しても旧版より頭が落ち着き、SW/NEの遊脚を追いやすい。低速は6つの姿勢の切り替え、高速は両足が重なる瞬間が目立つ。GIFのループでは比較開始位置へ戻るため、末尾の座標の巻き戻しはゲームの足滑りではない。

**実行確認：** Nodeと実PNGをデコードするCanvas環境で、両版の8方向、3速度、停止と方向転換、攻撃の全コマ、旧新切替時のアンカー、48/64の切り出し、描画補間オフを検証。サンプルした表示ピクセルと切り出し元の一致を確認。この場では入力受付とタイマーは再現できたが、人間の入力遅延や端末ごとの描画性能は測っていない。実Chromiumは自動起動が `socket() failed: Operation not permitted (1)`、別のブラウザ検証環境で開いたローカルHTTPは `net::ERR_CONNECTION_REFUSED`。実ブラウザ操作での検証は未実施。証拠と再試行スクリプトは `qa/`、`verify_preview.cjs`、`verify_browser.cjs`。

### 6. 技術上の不具合、見た目、制約

- **技術的に確認できたこと：** 120コマの透過PNG（アルファ0/255）とセル縁の余白、構え・歩行・攻撃アンカーの整合、旧静止画と同一の色・構え。剣と盾は取付手と同じ変換。剣の握りから先端は約11.687単位で固定。各離散ポーズで剣身の64個のソースボクセル中心を検査し、グリップを除く身体との重なりは検出しなかった。
- **見た目の問題：** NWの刃・腕の遮蔽、Wの遠側の足と局所的な髪の変化、E/SEの斬撃の短縮。停止時と急反転時は既存の静止姿勢に直接切り替わり、自然なブレンドはしない。
- **方式の限界：** 同じ3Dポーズでも、カメラ方向によって剣の弧が前後方向に短縮され、頭に隠れる。右腕をさらに外へ出すと一部の投影を救えるが、別方向の自然さや接地を損なうことがある。低解像度・整数ピクセルのサンプリングだけでは、全方向・全フレームの靴先や髪の安定は保証できない。
- **未確認：** コマ間を補間した連続運動での剣の身体貫通、衝突・ヒットストップと操作感、実機でのフレーム落ち、人間のプレイ評価。8方向で画像を生成できることと、全方向で良い斬撃に見えることは別。

### 7. 実用性判定

| 用途 | 判定 | 理由 |
|---|---|---|
| 静止8方向 | 有望 | 旧版ピクセルと同一。アンカー・方向順を保持 |
| 歩行8方向 | 有望 | 同期時の接地と床上視認性は十分に検証。急停止・旋回の自然さは条件に依存 |
| 攻撃8方向 | 条件付きで有望 | N/NE改善、NW・側面の意味の伝達にはまだ弱さ |
| 通常の2D RPGへの組み込み | 条件付きで有望 | 通常のRGBAシート・メタデータで利用できる。実ゲーム未統合 |
| アクションRPGへの組み込み | 条件付きで有望 | 800ms拘束と主斬撃370ms、横・背面の瞬間視認性は要調整。判定や入力予約は未実装 |
| モーションの再利用可能性 | 未確認 | 同リグ内でのパラメータ調整は可能。別体型の関節比では試していない |

### 8. 次の実験

1. まず実ブラウザで原寸のW/NW/N/NEを短く繰り返し、エフェクトなしで「どこに・いつ斬ったか」をブラインドで当ててもらう。原寸で不足する向きだけ、共通モーションの腕・胸・刃面の候補を再比較する。
2. 次に仮の敵1体を置いた小テストで主斬撃370msと短縮版を比較。歩行→攻撃→歩行、入力予約、ヒット確認を観察する。効果はモーション単体を比較したあとに追加し、改善の寄与を分ける。
3. 歩行は歩き始め・停止・180°方向転換の前後を記録。原寸で足先の逆移動が目立つ場合は、歩行クリップを長くせず支持足を保った中間コマと短い停止遷移を比較する。別キャラクターや新装備は次段階。

### ファイルと再生成

- ゲーム用：`output/walk.png`、`output/attack.png`、`output/idle.png`、`output/metadata.json`。歩行・攻撃は縦行S/SW/W/NW/N/NE/E/SE、横列は時間順。アンカーは歩行(24,40)、攻撃(32,48)。
- 確認用：`comparisons/*_v3.gif`、`walk_AB_*.gif`・`attack_AB*.gif`、`*_eight_direction_AB.png`・`native_vs_3x.png`・`tip_trajectory.png`。旧原版は `baseline/output/`。
- 元データ・コード：`generate.py`、`walk_motion.py/json`、`attack_motion.json`、`baseline/base/`、`output/posed_slices.npz`、`posed_part_ids.npz`、`joints.json`。
- PythonでNumPy/Pillowを導入し、ZIPのプロジェクト内で下記を実行。確認済みは NumPy 2.3.5 / Pillow 13.0.0。環境が変われば圧縮やフォントの差はあり得る。

```sh
python -m pip install -r requirements.txt
python generate.py
python compare.py
python package_assets.py
python verify_walk.py
python verify_attack.py
python validate_package.py
```

バイト一致の再試験は `python generate.py --out <空の出力先>` に続けて `python validate_package.py --rebuild <同じ出力先>`。オプションのNode試験には `@napi-rs/canvas`、実ブラウザ試験には Playwright とChromiumを使用する。
