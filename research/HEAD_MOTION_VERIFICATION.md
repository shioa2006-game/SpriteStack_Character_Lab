# 歩行時の頭部連動：標準仕様 `walk.head` の実装と検証

歩行中に頭が固まって見える問題を、共通の歩行リグで直した。今後の全キャラクターで使う標準仕様 `walk.head` を `character.json` に追加し、MAREN、AZURE RONIN、CRYSTAL MAGEに適用した。

- **共通処理**：`spritestack/rig.py` の `_walk_head`。頭は首の関節に乗り、胴の動きを追う。
- **キャラクターごとの違い**：`walk.head` の値と、胴の上下動 `walk.tuning.root_bob_scale` だけ。キャラクター用の歩行システムは作っていない。
- **頭の動かし方**：顔のボクセルが崩れないよう、頭は1.0単位（姿勢ボクセル2個、約1 px）刻みで動く。
- **既存キャラクター**：`walk.head` がないLARK・BRAMは従来の頭のままで、出力はRGBAで基準と一致する。
- **変えていないもの**：静止PNG、モデル、攻撃。

| | 改善前（公開中だった歩行） | 改善後 |
| --- | --- | --- |
| MAREN：頭の上端の行が動く方向 | 0 / 8 | 8 / 8（肩と同じコマで1 px、S方向は髪の頂点が2 px） |
| AZURE RONIN：同上 | 0 / 8 | 8 / 8（1 px） |
| CRYSTAL MAGE：同上 | 4 / 8（描画の誤差で揺れていた） | 8 / 8（1 px） |
| 目の画素がコマで変わる方向（RGBA） | CRYSTAL MAGEのS・SW・SE・E | CRYSTAL MAGEのSW・SE・E（Sは解消。Eは杖の手が顔の前を通るため） |
| `research.verify_walk` | 13項目 | 16項目（頭の3項目を追加）。MAREN・AZURE RONINはPASS 16、CRYSTAL MAGEはPASS 15・WARNING 1 |

比較図は [research/head/results/](head/results/) にある。`<名前>_head_before_after.gif` は8方向を上段が改善前、下段が改善後で並べ、`<名前>_head_crops.png` は頭と肩を6倍に拡大した全コマである。改善前の公開歩行は [research/head/baseline/](head/baseline/) に保持している。

## 1. 問題の確認

公開中の歩行の部位画像（`walk_part_ids.png`）で、頭の最上端の行を方向・コマごとに測った。MARENとAZURE RONINは、全8方向・全6コマで同じ行だった。頭の横位置の変化も0.3 px以内だった。脚、腕、裾、髪は動いているので、頭だけが貼り付けた絵のように見える。

原因は従来の頭の式にある。

- 頭は首の左右動の25%（`head_lateral_scale`）、骨盤の上下動の30%（`head_bob_scale`）しか追わず、回転もしない。
- 共通クリップの骨盤の上下動はLARKの体格に合わせた0.22単位である。MARENでは `root_bob_scale` 1.3を掛けて0.29単位（0.3 px）。その30%は0.09単位で、画素に現れない。
- 胴自体も上下動が1 pxに届かず、肩の行もほとんど動いていなかった。

## 2. 試行と分かったこと

### 回転は顔を壊す

最初に、胸の前傾を追う回転と、上下動に合わせたうなずき（3°）、左右の傾き（2°）を入れた。拡大して見ると、MARENのS方向で、ほとんどのコマで目が前髪に隠れて消えた。W方向では、目が出たり消えたりした。

### 半ボクセルの平行移動も顔を壊す

回転をやめて平行移動だけにしても、S方向の目が全コマで消えた。描画は1画素に光線1本で、目や口は1ボクセル（0.5単位、投影で約0.6 px）しかない。頭を半ボクセル動かすと、光線が当たるボクセルが変わり、細い特徴が抜ける。

頭だけを描き、従来の頭からずらした量ごとに目の画素数を数えた（姿勢ボリュームの描画、64 pxセル）。

| ずらす量（x 左右, y 前後, z 上下） | MAREN S | AZURE RONIN S | CRYSTAL MAGE S / SW |
| --- | --- | --- | --- |
| なし | 4 | 2 | 4 / 4 |
| z −0.5 | 4 | 2 | **2** / 3 |
| z −1.0 | 4 | 2 | 4 / 3 |
| x +0.5 | **0** | **0** | **0** / 1 |
| x +1.0 | 4 | 2 | 4 / 3 |
| y +0.5 | **2** | 2 | **2** / 1 |
| y +1.0 | **2** | 2 | **2** / 2 |

上下に1.0単位（2ボクセル）下げても、3体とも正面の目は保たれる。左右・前後の半ボクセルや前後の1.0単位では、目が消えるか半分になる。

### 結論

頭の移動は、従来の頭の静止位置からの差を1.0単位刻みに丸める。こうすると頭のボクセルは正確に平行移動し、顔は改善前の歩行と同じに描かれる。動かすのは主に上下で、胴と一緒に動かす。

## 3. 標準仕様 `walk.head`

`character.json` の `walk` に `head` を書くと有効になる。現行のキーと既定値は [技術設計](../docs/TECHNICAL_DESIGN.md#歩行と頭部連動) にまとめた。計算は次のとおり。

1. 頭の位置は首の関節の移動に `follow`（既定 `[1, 1, 1]`）を掛けたもの。さらに、上下動の深さ（最も低いコマで1）を `lag_frames`（既定0.25）コマ遅らせた値で `bob` だけ下げ、`surge` だけ前へ出す。左右動の割合で `sway` だけ横へずらす。
2. 従来の頭の静止位置（左右0、前後 `head_forward_offset`、上下 `root_level`）からの差を、`snap`（既定1.0単位）の倍数に丸める。
3. 任意の回転：胸のひねり・前傾の割合（`yaw_follow`・`pitch_follow`）、うなずき `nod_deg`、傾き `tilt_deg`。既定は0。48 pxでは顔が欠けるので使っていない。大きいセルや顔の大きいキャラクターで試すための値である。

値の範囲は読込時に検査する（例：`bob` 0〜1.5、角度は±6°以内）。`walk.head` がない設定は従来の式をそのまま使い、LARK・BRAMの出力は変わらない。

## 4. キャラクター別の設定

頭の上下は、胴の上下動と合わせて作る。胴の沈みが0.5単位を超えると、頭の差が1.0単位に丸められ、肩と同じコマ（1と4、着地後の荷重の時点）で1 px下がる。

| キャラクター | `root_bob_scale`（胴の沈み） | `walk.head` | 意図 |
| --- | --- | --- | --- |
| MAREN | 1.3 → 2.9（0.29 → 0.64単位） | `follow` [1,1,1] | 大股で力強い歩き。胴ごと沈み、頭がそれに乗る |
| AZURE RONIN | 1.2 → 2.0（0.26 → 0.44単位） | `follow` [1,1,1]、`bob` 0.15 | 軽い歩き。胴の沈みは浅く、頭の沈みを少し足して1 pxにする |
| CRYSTAL MAGE | 1.0（0.22単位、変えない） | `follow` [1,1,1]、`bob` 0.45 | 落ち着いた歩き。肩はほぼ動かさず、頭だけが静かに1 px沈む |

値を決めた理由は次のとおり。

- **CRYSTAL MAGE**：胴を沈めると（`root_bob_scale` 2.0）、杖の先が床より0.5単位下に出て `walk.ground` がFAILになった。そこで胴は変えず、頭だけを沈めた。
- **AZURE RONIN**：2.2〜2.7では、剣を持つ前腕の残存が1コマで79.2%になり、`walk.parts` の下限80%を割った。原因は細い部位の再サンプリングである。2.0では公開版と同じ83.3%だった。
- **MAREN**：胴を深く沈めたことで、長髪の揺れ角が上限12°に2コマで張り付いた。上下の追従を `follow` z 4.0から2.5へ下げ、上限を13°にした。揺れの範囲は6.9〜12.1°で、改善前の7.3〜11.0°に近い。

## 5. 技術検証

`research.verify_walk` に頭の3項目を追加した。`walk.head` がないキャラクターではSKIPになる。

| 項目 | 内容 | しきい値（`quality.json` の `walk.head`） |
| --- | --- | --- |
| `walk.head.motion` | 部位画像で、頭の最上端の行が各方向の6コマで変わる方向の数。満たさなければWARNING | `min_moving_directions`（既定8） |
| `walk.head.neck` | 頭の首の点と胸の首の関節の距離、および上への浮き。超えればFAIL | `max_neck_offset`（既定1.5単位）、`max_neck_rise`（既定0.5単位） |
| `walk.head.face` | 頭だけを描いた材質画像で、顔の材質（既定 `eyes`）の画素数をコマごとに数える。0になるコマがあればFAIL、数が変わればWARNING | `features` |

`walk.head.face` は頭だけを描いて数える。腕や杖が顔の前を通ることは頭の動きの問題ではないので、GIFで判断する。

結果は次のとおり（公開版との照合を含む）。

| キャラクター | 結果 | 頭の動き | 首との距離 | 目の画素（頭だけ） |
| --- | --- | --- | --- | --- |
| MAREN | PASS 16 | 8/8方向 | 0.47単位以下、上への浮き0.19以下 | 全方向で一定 |
| AZURE RONIN | PASS 16 | 8/8方向 | 0.63単位以下、浮き0.15以下 | 全方向で一定 |
| CRYSTAL MAGE | PASS 15、WARNING 1 | 8/8方向 | 0.83単位以下、浮き0.07以下 | SW・SEで沈むコマが4 → 3 px |

CRYSTAL MAGEのWARNINGは、2節の表にある「z −1.0でSWが3 px」と同じ現象である。改善前の公開歩行も、SW・SEで同じ4 → 3 pxの変化があり、Sでは4 → 2 pxだった。Sは改善後に一定になった。WARNINGは `quality.json` の説明に記録し、FAILには変えていない。

その他の歩行の検査（接地、足の滑り0、アンカー、装備の接触と左右、破片、腕の位相、装備の可視画素、布・髪の入り込み）は、3体とも引き続きPASSである。布・髪が他の部位に入り込む割合は、剛体のままより少ない。

### 回帰

| 対象 | 結果 |
| --- | --- |
| LARKの全モード | `verify_rebuild` 合格。静止・歩行・攻撃のRGBAが公開版と一致 |
| BRAMの全モード | `verify_bram` 合格。静止・歩行・攻撃のRGBAが公開版と一致 |
| MAREN・CRYSTAL MAGE・AZURE RONINの静止 | 汎用検証の結果は変更前と同じ（MAREN PASS 33・WARNING 1、CRYSTAL MAGE PASS 44・WARNING 1、AZURE RONIN PASS 64）。公開PNG・JSONと一致 |
| 旧来の検証 | `verify_maren`・`verify_crystal_mage` 合格。汎用検証の自己テスト20/20 |
| 共通関数の移動 | `cyclic` を `secondary.py` から `rig.py` へ移した。従属運動の計算は変わらない |

## 6. 視覚評価

技術検証とは分けて評価した。見たのは次の3つである。

- 改善前後のGIF（3倍、[research/head/results/](head/results/)）
- 頭と肩を6倍に拡大した全コマ
- 歩行GIF（原寸と3倍、[research/walk/results/](walk/results/)）

GIFの再生はコマ送りで確認した。ゲーム内の速度での見え方は未確認である。

**MAREN**

- 着地後の荷重のコマ（1と4）で、肩・胸・頭が一緒に1 px沈む。8方向とも、頭が胴の上に乗って弾む見え方になった。
- S方向では髪の頂点が2 px下がり、頭頂の丸みが1コマだけ少し平らになる。目・口・前髪の形は変わらない。
- 長髪の揺れは改善前と同じ程度で、背中で揺れる。

**AZURE RONIN**

- 頭は8方向とも肩と同じコマで1 px沈む。
- 胴の沈みは0.44単位（約0.5 px）で、胸の上端の行が動くのはS・SEなど一部の方向だけである。そのため、頭が首元へ少し沈むように見える。
- 動きは軽く、コミカルには見えない。ポニーテールは頭と一緒に下がり、そのあと遅れて揺れる。

**CRYSTAL MAGE**

- 頭だけが静かに1 px沈み、肩と杖はほとんど動かない。落ち着いた印象は保たれた。
- 改善前はS方向の2コマで目の形が変わり、まばたきのように見えていた。改善後は消えた。

**全体**

- 3体とも頭が上下するのは2コマ／周期で、過剰な揺れはない。
- 左右・前後の頭の動きは入れていない。2節の理由により、48 pxでは顔が崩れるためである。
- S・N方向の左右の重心移動は、改善前と同じく胴の0.5 px未満の動きだけである。

## 7. 残る課題と未確認事項

- **頭の左右・前後の動き**：仕様（`sway`・`surge`）はあるが、48 pxでは顔が崩れるので使っていない。顔の目が2ボクセル以上あるモデルや、64 pxセルで試す余地がある。
- **回転（うなずき・傾き・頭の向き）**：同上。目のボクセルを大きくするか、頭を別の解像度で描くといった描画側の工夫が必要で、今回は行っていない。
- **頭の上下の大きさ**：1 px単位でしか表せないため、3体の差は胴の沈み方とタイミングでしか出せていない。
- **MARENのS方向**：頭頂の行が2 px下がる。1.0単位の移動が投影で1.09 pxになり、髪の輪郭の丸めがずれるためである。
- **LARK・BRAM**：`walk.head` を入れていない。どちらも従来の頭で、頭の上端の行は動かない。既存の公開成果を変えない方針による。適用する場合は、AGENTS.mdの手順で基準画像を更新して行う。
- **未確認**：実際のゲーム速度での見え方、停止・方向転換へのつなぎ。

## 8. 再現手順

```powershell
$python = ".venv\Scripts\python.exe"
$run = "output\head-check"
foreach ($name in "maren", "azure_ronin", "crystal_mage") {
  & $python -B -m spritestack --character "characters/$name/character.json" --modes walk --out "$run/$name"
  & $python -B -m research.verify_walk --character "characters/$name/character.json" --out "$run/$name"
}
& $python -B -m research.head.compare --after $run --out "$run/head-comparison"
& $python -B -m research.walk.compare --after $run --out "$run/walk-comparison"
```

公開中の `docs/assets/<名前>/walk.png` と `walk.json` は、この手順の出力と一致する（`walk.published` がPASS）。
