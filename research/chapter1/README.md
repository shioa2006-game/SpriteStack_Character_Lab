# 第一章の仕掛け　鉄の輪・的・跳ね橋・遺跡の扉・霜の水晶・石像

6個の編集可能な立体から10状態・各8方向を生成した。OBJECTSではGUILDWARDの制作候補に登録している。[通常倍率の配置プレビュー](../../docs/chapter1.html) · [配置例](installation.png) · [作動後の配置例](activated.png)

**実ゲームの画面。** 元のゲームのChrome画面でm2の輪と的、m4の格子・灯・水晶・石像、m7の橋板と両岸を確認した。命中後・点灯後・開放後・降橋後はゲームの検証用入口で各フラグを設定して撮影した。m4は格子を上げると通行可能になり、m7は橋を下ろした時だけ谷の対象マスが立てる面になった。m7はカメラを反対側に回すと橋板が岸の陰から見える。m8の配置はマップデータで照合した。

**Labの仮配置。** 新素材の取付け、両岸への接触、人物・壁・氷床との大小関係はLab側で確認した。プレビューの水路は橋の下の空間を読み取るための仮地形。m7・m8の実マップは谷である。第一章の橋の設置先、マップに明示されない壁の法線、地形によるクリック領域・前後の遮蔽はゲーム統合時に確認する。現行の描画は4方向、納品は将来のカメラを含む8方向。

## 設置・方向の引き渡し

水平方向1マス14×14、鉛直1段8モデル単位。通常の素材は0.5単位の材質・部位格子を既存の剛体ベイクに渡し、正投影24°、1.50 px/単位で出力した。輪郭はRGB(37,29,41)、光はカメラ左・手前・上（−0.42, +0.32, +0.85）。PNGには物体とその取付金具だけを収める。壁、岸、氷、水面、比較用の人物はプレビューで重ねる。[プロジェクトの縮尺](../GUILDWARD_ASSET_SCALE_GUIDE.md)

| 素材 | セル px / 原点 px | モデル空間で指定する点・面 |
| --- | --- | --- |
| 鉄の輪 | 44角 / (22,31) | 壁面Y=0、表は+Y。固定点 `mount=(0,0,13.5)`、縄を掛ける内周の金属 `hook=(0,3.5,12)`、穴の中心 `aperture=(0,3.5,7.5)`。マスを塞がない |
| 的 | 48角 / (24,32) | 壁面または下地の取付点 (0,0,6.5)。横軸+X、支点 (0,2.75,6.5)。中心は使用前 (0,4,11.5)、−90°の命中後 (0,7.75,5.25) |
| 跳ね橋 | 64角 / (32,38) | 原点は近岸の縁と歩行面の交点。軸+X、支点 (0,0,−1)。上90°・下0°。踏面はY=0から14、Z=0。中央 (0,7,0)、安全な支持域の半幅 (5,6.5)。元岸の中心は (0,−7,0) |
| 遺跡の扉 | 72角 / (36,55) | 敷居中央 (0,0,0)、案内軸+Z。格子は27単位せり上がり梁の中へ収納する想定。公開2状態は閉じた格子と収納後の固定枠。回転支点の代わりに `geometry.slide` が案内原点・軸・行程・収納高さを持つ |
| 霜の水晶 | 48角 / (24,35) | 石座中央 (0,0,0)、作用点 (0,0,11)。3本の結晶と霜を同じ格子に保持し、消灯時は霜の部位を非表示にする |
| 石像 | 52角 / (26,39) | 台座中央 (0,0,0)、顔 (0,5,16)、正面+Y。台座と本体を同じアンカーで置く |

ゲームの占有判定は各JSONの `occupied_tiles` と状態表を使う。門の幅17には左右の壁に掛かる梁、橋の全幅16には岸に固定する軸頭、水晶の幅14.5には外へ張り出す霜の先端が含まれる。これらの張り出しは隣のマスを占有しない。輪・的は作用点を持つ通行可能なマス、石像・水晶は同じ1マスでも通行を塞ぐ。

- **Lab標準PNG** は `docs/assets/<id>/<state>.png` の横一列。列番号0〜7は **S / SW / W / NW / N / NE / E / SE**、モデルから見たカメラヨーは0, −45, …, −315°。各方向を同じ姿勢の立体から個別に投影した。通常は `metadata.json`、他状態は同名JSONの `neutral.cell / anchor` で切り出す。GIFは8方向の確認用一覧。
- **ゲーム投影PNG** は現行32×16 pxタイル、1段8 pxに合わせて立体を再投影した透過アトラス。同じキー `<id>/<state> → 方向 → [0]` の `rect=[x,y,w,h]` を切り出し、画面上の設置原点に `offset` を足して左上を置く。標準PNGもゲーム投影も最終表示で最近傍整数倍にする。[ゲームPNG](../../docs/studies/chapter1/game.png) · [矩形・オフセット](../../docs/studies/chapter1/game.json)
- **接続点** は各状態の `placement.points_xyz` に記録。2D合成用に、方向・投影別の `offsets_px_from_anchor` も用意した。原点とオフセットを加えてから画素に丸める。たとえばSW・ゲーム投影では鉄の輪の穴が原点から (−4,−5.5) px。縄先は同じ表の `hook` を使う。門の `r1…r4` は固定枠上の灯の中心で、マップのフラグ順に独立に点灯できる。[接続点の対応表](../../docs/studies/chapter1/placement.json)
- **マップ上の方位と設置原点** は別表の `tile_origin_xy`（ゲームの整数がマス中央）、`origin_z_model`、`heading_deg` で指定した。世界位置は `(14i,14j,Z) + Rz(heading) × localXYZ`。シートの行・列選択に使うヨーは `cameraYaw−heading`。m7の例は原点 (147,42,32)、heading=+90°。遠端は (133,42,32) で西岸の縁に合う。壁面の向きがマップ未指定でも実装担当者が試せるよう、地図の事実とLabが推奨する姿勢を区別した。[マップ別設置表・フラグ対応](../../docs/studies/chapter1/map-placement.json)

m1は輪のマスが平らなため、推奨配置では地形描画側の支えに座金を接する。m2は南側の段差面、m3は東側の岩棚面を想定する。台座や壁面の意匠はシートから独立して交換できる。門の造形はm4の高さ4段に合わせた。m2の倉はルール上3段で、原作描画は両方に同じ22 pxの昇降処理を使う。倉に転用する場合の柱高と外観は採用時に決める。

## 再生成と検証

```powershell
$py = (Resolve-Path .venv/Scripts/python.exe).Path
$run = Join-Path $PWD ('.phase1/chapter1-' + [guid]::NewGuid())
& $py -m research.chapter1.export --out "$run/bake"
& $py -m research.chapter1.verify --out "$run/verify"
& $py -m research.verify_objects --out "$run/objects"
node research/verify_catalog.cjs
```

1回の書き出しで `bake/models/<id>.npz` に材質・部位の水平断面、`bake/assets/<id>/` に標準シート・GIF・JSON、`bake/study/` にゲーム投影と接続点表ができる。原型は各素材の `objects/<id>/build_model.py` と `object.json` を編集する。鉄の輪と跳ね橋だけ先に出す場合は `--only iron_ring drawbridge` を付ける。`map-placement.json` は地図から決めた設置契約として手元で管理する。

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory docs
# 別ターミナルで実行。Playwright PythonとChromeを使用
python -m research.chapter1.browser_check --url http://127.0.0.1:8000 --browser "C:/Program Files/Google/Chrome/Application/chrome.exe" --out .phase1/chapter1-browser-new
```

[仕掛けのプレビューを開く](http://127.0.0.1:8000/chapter1.html)。通常2倍と原寸、両投影、方向、個別状態を選べる。下段の8方向一覧は背景から分離した姿を表示する。

**直した箇所。** 最初の2種を仮置きした後、輪の内径を広げ、内縁に明部を加えた。橋板の木口と継ぎ目、裏の斜材を強調し、横軸中央を少し細くして近岸の踏面まで板が連続するようにした。残り4種の原寸比較では、水晶の両脇の枝を離して雪面に負けない輪郭にした。石像は顔面を前へ出して暗い眼を彫り、石柱と人物をずらして三者の前後を確認できるようにした。

**検査結果。** 6原型を独立した出力先で作り直し、材質・部位、10シート80セルのRGBA、GIF、公開メタデータ、ゲーム投影アトラスと接続点表が一致した。輪はS/SW/SEで穴中央が両投影とも透過し、W/Eでは厚みが見える。橋は固定軸、両岸の天端、上がったときの空隙を実格子で検査。門は両状態で梁を保ち、中央通路を開放する。真横W/Eの格子は柱の陰に隠れる。Chromeで全80セルを元PNGと照合し、配置画面で両投影・全8方向・状態切替を確認した。[生成](export.py) · [立体と接続点の検査](verify.py) · [ブラウザ検査](browser_check.py)
