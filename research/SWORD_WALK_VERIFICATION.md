# MAREN・AZURE RONIN 歩行の剣のしなり修正

本稿の対象は歩行の輪郭改善。後に同じ描画設定を剣士2体の攻撃にも適用した。[MARENの攻撃](MAREN_DYNAMIC_SLASH.md) · [RONINの攻撃](AZURE_RONIN_QUICK_SLASH.md)

2026-11-22。MARENとAZURE RONINの歩行で、剣がしなったり、折れたり、途切れて見える問題を直した。武器を独立した資産に分けることはせず、既存のモデル、共通リグ、ベイクの仕組みはそのまま使った。歩行の描画だけに、剣の画素の決め方の設定 `walk.fine` を加えた。原因の分析は[武器分離の設計調査](WEAPON_SEPARATION_DESIGN.md)による。

## 結論

- **採用した方法**：剣の部位を、1画素あたり4×4本の光線で描き直す。半分以上覆われた画素と、細い刀身を横切る方向で最も覆われた画素（覆いが1/4以上）を剣にする。1本の光線で剣になる画素はそのまま残す。さらに、剣が別の面の前にあるときは、剣の画素を暗くせず、剣の後ろの面に暗い境界線を引く。
- **効果**：E方向の剣は、MARENで3片・途切れ8から1片・途切れ2になった。残る途切れは握りの手の下と先細りの切っ先で、改善前からある。AZURE RONINは途切れ3から1になった。最大の中心線のずれは、MARENが1.16から1.01 px、AZURE RONINが1.28から1.13 px。
- **いちばん効いた変更**：境界線の位置の変更。E方向では、剣の画素の約半分以上が最も暗い色で描かれていた（MAREN 51%、AZURE RONIN 67%）。改善後はどちらも1割以下で、暗いコートや明るい上着の上でも1本の刀身として見える。
- **太さ**：剣身の平均の幅は、MARENが11%、AZURE RONINが16%増えた。設計調査で試した4×4本・覆い25%の方法（30〜50%増）より細い。
- **変わらないもの**：静止画像、LARK・BRAMの全出力、CRYSTAL MAGEの歩行、頭部・接地・衣装の動きは改善前と同じ（後述の回帰確認）。手首角度、刀身の形、モデルは変えていない。

## 改善前の見え方と原因

公開中の歩行（`06d6b14` 以降の頭部連動版）を4〜10倍に拡大して確かめた。

- **E方向**：MARENの剣はコートと脚の上で点線のように途切れ、折れたように見える。AZURE RONINは3〜5コマ目に鍔の近くで刃が切れる。
- **NE方向**：剣はおおむねまっすぐだが、コマごとに画素の段差の位置が変わり、刃がたわむように見える。

原因は2つあった。

1. **1画素1光線の取りこぼし**（設計調査で確認済み）：E方向では刀身が真横に近く、投影すると1画素より細くなる。画素の中心を通る1本の光線では刀身に当たらない画素が出て、途切れる。
2. **境界線の暗色化**（今回の調査で判明）：描画は、ある面がすぐ隣の画素の面より1.8単位以上手前にあると、その画素を材質の最も暗い色にして境界線にする（`render.py` の `seam`）。幅1 pxの刀身が体の前にあると、刀身のほぼすべての画素がこの境界になり、最も暗い色で描かれる。剣の暗い色（MARENの `2f3640`）はコートの色（`383035`）とほとんど同じ明るさで、刀身が消えて見える。明るく残った画素だけが点のように並ぶ。

## 採用した方法

`characters/maren/character.json` と `characters/azure_ronin/character.json` の `walk` に次を加えた。

```json
"fine": {
  "parts": ["sword"],
  "rays": 4,
  "coverage": 0.5,
  "line": 0.25,
  "seam": "behind"
}
```

処理は [spritestack/render.py](../spritestack/render.py) の `Renderer._fine` と、`render` の境界線の部分にある。ベイクは歩行の各コマ・各方向で `fine_parts(character, "walk")` を渡す（[spritestack/bake.py](../spritestack/bake.py)）。`fine` がないキャラクター、静止、攻撃は、これまでと同じ描画になる。

1. **対象の範囲**：剣の姿勢ボクセルを投影した範囲（周りに1ボクセル分の余白）だけを描き直す。
2. **光線**：範囲の各画素に4×4本の光線を通す。光線ごとに、剣が最初に当たる面か（見える）、剣より手前に別の面があるか（隠れる）を記録する。
3. **剣にする画素**：剣の形（見える光線と隠れる光線の合計の割合）で決める。手前の物は数えない。
   - 形が1/2以上覆う画素は剣にする。
   - 刀身を横切る方向で最も覆われた画素も剣にする。具体的には、x方向かy方向で両隣以上の値を持ち、1/4以上覆う画素である。真横から見て1画素より細い刀身でも、1画素ずつつながる。
4. **遮蔽**：剣にする画素でも、見える光線の割合が1/4未満か、隠れる光線より少なければ、手前の物を描く。握りの手、腕、体の後ろの剣は、これまでどおり隠れる。
5. **既存の画素**：画素の中心の1本の光線で剣が見える画素は、そのまま剣にする。
6. **色**：新しく剣にした画素の材質と陰影は、剣の形だけで決めた1つのボクセルから取る。その画素の中心の光線で最初に当たる剣のボクセル、なければ中心に最も近い光線のボクセルである。剣だけを描いたときも同じボクセルになるので、ベイクの可視画素の照合（全体の描画で見える剣の画素は、剣だけの描画にもある）が成り立つ。
7. **境界線**：剣の画素が隣の別の面より手前にあるとき、剣の画素を暗くせず、隣の面の画素を、その面の最も暗い色にする。体やほかの部位どうしの境界線は変えない。

## 目視による評価

`research/sword/results/` の原寸の8方向GIF（3倍）、NE・E・W・NWの剣の周りの8倍GIF、全コマの6倍の拡大図で確かめた。技術的な合否とは別に記録する。

- **E方向**：改善前は、暗い点と明るい点が並ぶ途切れた線だった。改善後は、両体とも手から切っ先まで明るい1本の刃が続き、連続再生でも硬い金属の板が脚の前を動いて見える。AZURE RONINの刃は、明るい上着の上でも後ろの暗い境界線で縁取られて分かれる。
- **NE方向**：中心線のずれが減り（MAREN 0.88 → 0.72 px）、連続再生でのたわみの印象は弱まった。ただし、剣の角度が歩行で約10°変わるので、画素の段差の位置はコマごとに動く。これは48 pxで角度が変わる以上なくせない（設計調査の「残る限界」）。
- **S・SW・N・SE**：形は改善前とほぼ同じで、幅がわずかに増えた。SEでは、脚の上の刃が明るくなって読みやすくなった。
- **AZURE RONINの反り**：S・SW・N・NEで、改善前と同じ弧に見える。中心線のずれは反りを含む理想形状からの差で、増えていない。
- **W・NW**：体の後ろに回る剣の隠れ方は改善前と同じ。
- **手との接続**：全方向で剣は握りの手から出ている。N方向でも手袋の画素は残る。比較の段階で、覆い1/4以上の案では、Nの2・3コマ目で手袋が刃に置き換わった。採用した方法では、手前に手がある画素の保護によってこれを防いだ。
- **原寸48×48**：E方向の剣は、改善前は脚の模様のように紛れていたが、改善後は剣として読める。全体の太さは画風に収まっている。ただし、MARENのS・Nの幅2 px強の刀身は、改善前より少し重く見える。

## 回帰確認

- **LARK・BRAM**：全モードを焼き直し、静止・歩行・攻撃のRGBAが公開版と一致した。`verify_rebuild` と `verify_bram` はPASS。
- **静止**：MAREN・CRYSTAL MAGE・AZURE RONINの静止を焼き直し、汎用検証の結果は改善前と同じだった（MAREN PASS 33・WARNING 1、CRYSTAL MAGE PASS 44・WARNING 1、AZURE RONIN PASS 64）。`verify_maren`、`verify_crystal_mage`、`research.verify_character_selftest`（20/20）もPASS。歩行のベイクに含まれる静止画像も、公開版と一致する（`walk.idle_kept`）。
- **CRYSTAL MAGEの歩行**：`fine` がないため、公開版と一致した。`verify_walk` の結果は改善前と同じで、`walk.head.face` の既知のWARNINGが1件残る。
- **MARENとAZURE RONINの歩行**：`research.verify_walk` は両体ともPASS 16、WARNING 0、FAIL 0。次の項目はすべてPASSで、値は改善前と同じ：
  - 接地・足の滑り（`walk.contact`、`walk.ground`）
  - 部位の残存・装備と手の接続（`walk.parts`、`walk.items`）
  - 衣装・髪の揺れ（`walk.secondary.*`）
  - 頭部の連動（`walk.head.*`）
  - アンカー
  - 剣の可視画素の最小値：MARENは1 px（NW 1コマ目）のまま。AZURE RONINは3 pxから4 pxに増えた。盾は1コマで1 px減ったが、最小値は6 pxのまま。
- **姿勢・動き**：関節、変換、姿勢ボリュームは変えていないので、変化はない。変わるのは剣の周りの画素の色だけである。

## 仕様・不具合・未確認事項

- **仕様**：`walk.fine` は歩行だけに効く。静止と攻撃の描画は変わらない。キーは次のとおり。
  - `parts`：対象の部位
  - `rays`：1画素の1辺の光線数（2〜8）
  - `coverage`：形で剣にする覆いの割合
  - `line`：最大の画素の下限。省略すると、見える光線の割合が `coverage` 以上の画素だけを足す。
  - `seam`：`front` が従来の境界線、`behind` が剣の後ろに引く境界線。
- **仕様**：剣の後ろの境界線は、体の画素の色を変える（その面の最も暗い色）。これは剣の周りだけで、剣の画素の部位IDは変わらない。
- **既知の限界**：NE方向などで、剣の角度の変化による画素の段差の移動は残る。理想形状でも0.5 px前後のずれが出る（設計調査）。
- **既知の限界**：MARENのS・Nは、刀身の幅が平均で約0.1〜0.2 px増えた。
- **未確認**：攻撃には使っていない。MARENの攻撃は公開しておらず、AZURE RONINの攻撃も公開していない。攻撃の大きな角度変化でこの方法が合うかは未確認。
- **未確認**：盾・杖・本には使っていない（CRYSTAL MAGEは `fine` なし）。
- **ベイク時間**：剣の範囲だけを描き直すので、歩行のベイクは両体とも1分前後で、改善前と大きく変わらない。
